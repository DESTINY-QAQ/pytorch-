B、T、C、H：形状不是密码

目标：看到 [B,T,C] 或 [B,H,T,T] 时，能说出每个维度是什么、为什么存在、会影响什么。

回到互动总课术语表

先记一句：B 是一次并行处理几条序列；T 是每条序列有几个 token；C 是每个 token 用多少个数字表示；H 是把 C 维表示切成几路并行注意力。

从一个真的 batch 开始

第 0 条序列: [Transformer, 学习, 从, token]
第 1 条序列: [注意力, 读取, 上下文, 。]

token_ids.shape == [2, 4]        # B=2，T=4
hidden.shape    == [2, 4, 8]     # C=8

它表示 2 条句子 × 每条 4 个 token × 每个 token 8 个浮点特征。hidden[1,2] 就是第 1 条句子的第 2 个 token 的 8 维向量。

B：batch size，一次处理几条序列

B 的作用是并行。它不改变某个句子的意思，主要影响吞吐量、显存与一次梯度估计。当前项目训练时取 batch_size=16，因此 x.shape = [16,32]：同时从语料中取 16 段、每段 32 token 的文本。

x, y = get_batch(data, batch_size=16, block_size=32, device=device)
logits = model(x)     # [16,32] → [16,32,vocab_size]

T：sequence length，每条序列有几个 token

T 决定这一步能使用多长的上下文。教学模型中 block_size=32，所以训练样本每段为 32 个 token。注意力要让每个 Query 与每个 Key 比较，因此每个头都会产生一个 T×T 的分数表。

若 T=4，一个头的 scores 是 [4,4]：
Query 0 只能看 Key 0
Query 1 能看 Key 0、1
Query 2 能看 Key 0、1、2
Query 3 能看 Key 0、1、2、3

因果 mask 遮住未来位置。T 从 32 加到 64，注意力表从 32²=1024 格变为 64²=4096 格；长度翻倍，主要注意力计算约变四倍。

C：d_model，每个 token 的表示宽度

C 是一个 token 隐藏状态的特征数。Embedding 把整数 ID 查成 C 维浮点向量，注意力、FFN 和残差连接都保持主干为 [B,T,C]。C 更大表示空间更宽，但线性层与 FFN 的参数和计算通常也更多。

cfg.d_model = 96
self.token_embedding = nn.Embedding(vocab_size, 96)
x = self.token_embedding(token_ids)  # [B,T] → [B,T,96]

不要把 C 的第 0、1、2 维理解成固定的人类概念；它们是训练学出的坐标，整体向量和后续层共同形成有用表示。

H：heads，把 C 维表示切成几路注意力

通常固定 C 后，H 把每个 token 的向量分成 H 份，每头宽度 D=C/H。本项目的 C=96, H=4，所以每头 D=24。C 必须能被 H 整除。

x:      [B,T,C]   = [16,32,96]
q/k/v:  [B,H,T,D] = [16,4,32,24]
scores: [B,H,T,T] = [16,4,32,32]
out:    [B,T,C]   = [16,32,96]

源码里的 view(batch, time, n_heads, head_dim).transpose(1, 2) 正是在做这个拆分与调换顺序。H 并不是多复制 H 份完整模型；它是在同一个 C 维总宽度内提供多路并行的注意力计算。

一条形状路线

IDs [B,T] → Embedding [B,T,C] → Q/K/V [B,H,T,D]，D=C/H → scores [B,H,T,T] → 合并后 [B,T,C] → logits [B,T,V]

PyTorch 的 batch_first=True 也把输入输出写成 (batch, seq, feature)，并明确说明 embed_dim 会分给 num_heads。这与本项目的 [B,T,C] → [B,H,T,D] 完全一致。PyTorch 文档

两个实际例子

场景B、T、C、H读出来的含义
本项目训练16,32,96,416 段文本；每段 32 token；每 token 96 维；4 个头各处理 24 维；每头有 32×32 的注意力表。
聊天生成1,128,768,12只生成一条回答，但需看 128 个历史 token；每头 64 维；较大的 T 使 KV cache 更重要。
报错排查C=10,H=3不合法：10 无法均分为 3 个头。可改为 C=12，或改 H=2/5。

检索练习：x 是 [16,32,96]，H=4。scores 的形状是哪一个？

最实用的判断法：先问有几条序列，得到 B；每条多长，得到 T；每个 token 多宽，得到 C；C 被分成几路注意力，得到 H。看到 [B,H,T,T] 时，就想到每个 batch、每个头都有一张 token 对 token 的注意力表。
