Lesson 05 · 35–60 分钟

从零训练一个小型 Decoder Transformer

目标不是生成高质量中文，而是亲手走完整个训练闭环：ID → embedding → causal attention → logits → loss → 反向传播。

课程主页形状速查

先做两项安全检查

python -c "import torch; print(torch.__version__)"
python code/transformer_from_scratch.py --smoke

--smoke 不训练，只检查 MHA、GQA、MoE 与完整模型的输出形状。只要它打印 all smoke tests passed，再开始训练。

开始训练

python code/transformer_from_scratch.py --train --steps 300
# 想更快验证流程：
python code/transformer_from_scratch.py --train --steps 30

脚本用一段极小语料做字符级 tokenization。这是刻意的教学简化：你能马上跑通流程。真实 LLM 会换成 BPE/SentencePiece；模型主体的数据流不变。

训练循环只有五件事

1
取批次：x 是长度 T 的前文 ID，y 是右移一格的目标 ID。
2
前向：模型输出每个位置对词表全部 V 个候选的 logits，形状为 [B, T, V]。
3
损失：交叉熵把 [B, T, V] 与 [B, T] 的正确 ID 比较。
4
反向传播：loss.backward() 计算所有参数的梯度。
5
更新与生成：优化器更新参数；生成时每轮只把最新预测 token 拼到输入尾部。

读代码的推荐顺序

  1. TinyCharTokenizer：最简 token ↔ ID 映射。
  2. MultiHeadSelfAttention：追踪 [B,T,C] 如何变为 [B,H,T,D]。
  3. DecoderBlock：注意力、残差、LayerNorm、FFN 的组合。
  4. MiniTransformer：token/position embedding、堆叠 block、输出层。
  5. train_demo：交叉熵与采样生成。
你真正理解的标志：能把 n_heads、n_layers、block_size 任意改一个，预测哪一个张量形状或资源开销会变化，然后运行验证。

三道自测（请先不看答案）

  1. 若词表从 V=100 改为 V=1000，哪两个大矩阵会变大？
  2. 若 block_size 加倍，训练阶段 attention score 的大小如何变化？
  3. 为什么生成时只缓存 K/V，而不缓存整个 attention score 矩阵？
