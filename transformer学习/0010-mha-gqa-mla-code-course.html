第 0 课 · 先排除错误前提

四个缩写并不是四种同类机制

MHA、MQA、GQA、MLA 都属于注意力结构；MoE 通常替换 Transformer block 的 FFN。DeepSeek-V2 同时使用 MLA 与 MoE，是因为它们优化的是两个不同子层，不是因为 MoE 是一种注意力。

第 2 课 · 从一个 Query 开始

Q 在提问，K 在报名，V 是真正取回的信息

Q

Query：我想找什么？

当前 token 经过可学习投影后形成查询向量。它不是一句自然语言问题，而是一组训练出来的数字。

K

Key：我适合被怎样匹配？

每个可见 token 提供一个键。Q 与 K 的点积越大，通常表示当前投影空间里越匹配。

V

Value：选中我后拿走什么？

softmax 权重不会直接加权 K，而是加权 V。K 用于寻址，V 承载被读取的内容。

scores = Q @ Kᵀ / √D
weights = softmax(scores + causal_mask, dim=-1)
output = weights @ V D 是每个头的维度，不是 d_model 的任意别名；mask 在 softmax 之前加入。

MASK LAB

为什么除以 √D？

若 Q/K 各维尺度相近，点积方差随 D 增大。logit 过大会让 softmax 过尖、梯度不稳定；缩放把量级拉回更合适的范围。

mask ≠ 位置编码

mask 只控制“能不能看”；RoPE/位置编码告诉模型位置或相对距离。脚本有 causal mask，但三种模块都没有位置编码。

一个头不一定等于一种人类规则

“语法头”“长距离头”可以帮助建立直觉，但实际头通常是分布式协同的，不能保证可被唯一命名。

softmax 沿哪一轴？

每个 Query 要在所有 Key 上分配权重，因此对最后的 Key 轴做 dim=-1。沿 batch 或 token 行之间归一化都会改变问题。

第 3 课 · Multi-Head Attention

多头最难的不是公式，而是四个轴的搬运

输入主干使用 [B,T,C]。把通道 C 均分给 H 个头后，每头维度 D=C/H，注意力内部使用 [B,H,T,D]。

SHAPE LAB

代码中的一次 QKV 投影，不是三层神经网络

self.qkv = nn.Linear(d_model, 3 * d_model, bias=False)
q, k, v = self.qkv(x).chunk(3, dim=-1)

Linear 只执行一次：[B,T,C] → [B,T,3C]。随后 chunk 只是把最后一轴切成三段，不新增参数。数学上可视为三张投影矩阵拼在一张大权重里。

已实现的核心

Q/K/V 投影、拆头、缩放点积、因果遮罩、softmax、加权 V、合并头。

脚本明确缺少

标准输出投影 W^O、dropout、padding mask、RoPE/位置编码、残差、LayerNorm、真实 KV Cache。

* 与 @

PDF 伪代码写 X * W 容易误导 Python 新手。在 PyTorch 中 * 是逐元素乘；线性代数乘法使用 @，Linear 内部也做矩阵乘与可选偏置。

view → transpose

[B,T,C] 先看作 [B,T,H,D]，再交换轴 1 和 2。只写数值形状可能看不出 T/D 恰好相等时的转置，所以必须同时记轴名。

第 4 课 · 从 MHA 到 MQA / GQA

Query 头不减少，减少的是独立 K/V 头

Q: [B, H, T, D]
K,V: [B, G, T, D]
repeat = H / G 必须满足 H % G == 0。G=H 是 MHA；G=1 是 MQA；中间值是一般 GQA。

改变查询头数 H 与 KV 组数 G。每张卡表示一个独立 Query 头。

GROUP LAB
结构Q 头KV 头每个 KV 头服务相对 MHA 缓存
MHAHH1 个 Q 头1
GQAHGH/G 个 Q 头G/H
MQAH1全部 H 个 Q 头1/H
PDF 第 7 页的关键错误GQA 仍有 H 个不同 Query 头，每个都要与其对应的 K 计算注意力分数。它不会把主要 QK 点积次数简单降成 G/H。更可靠的说法是：GQA 减少 K/V 投影宽度、KV Cache 和解码时反复读取 K/V 的带宽。
源码的 repeat_interleave 是教学桥梁它真的把 [B,G,T,D] 物理复制成 [B,H,T,D]，方便复用普通注意力函数。生产级 kernel 通常直接表达共享关系，避免这份中间复制；因此不能用该 forward 的峰值内存测真实 GQA 节省。

第 5 课 · Multi-head Latent Attention

“压缩后恢复”只讲对了一半

脚本的 ToyMLA 准确展示联合低秩瓶颈，但真实 DeepSeek-V2 MLA 还需要查询压缩、解耦 RoPE 与矩阵吸收。点击切换，比较两层理解。

低秩联合 K/V 压缩

ctKV = WDKV ht
ktC = WUK ctKV
vtC = WUV ctKV K 与 V 共用同一个 c^KV，不是各缓存一份 latent。

在 ToyMLA 中，两层之间没有激活函数，所以联合映射等价于 W_restore @ W_compress，秩至多为 latent_dim。这就是压缩约束：省存储不是免费午餐，它限制了可表达的线性映射。

查询压缩

真实 MLA 也可把 Query 先降维再升维，主要用于降低训练激活内存；历史 KV Cache 不存过去 Query，因此它不是缓存节省的主体。

解耦 RoPE

内容 K/V 与位置分量分开，额外共享位置键 k^R。因此真实缓存不是只有 d_c，而是每 token、每层 d_c+d_h^R 个元素。

矩阵吸收

K 上投影可吸收到 Query 侧，V 上投影可吸收到输出投影，使推理时不必像 ToyMLA 那样显式恢复完整 K/V。

不能外推速度

教学脚本没有增量解码、cache 接口和专用 kernel。它打印的是“若缓存 latent”的元素数，不是一次真实 MLA 性能基准。

论文中的可核验例子DeepSeek-V2 设 d_c=4d_h、d_h^R=d_h/2，因此 MLA 缓存约为 4.5d_h 元素/层/token，等价于只有 2.25 个 KV 组的 GQA 缓存量。这个结论来自特定架构，不等于所有 MLA 配置。

第 6 课 · 把“省显存”算成数字

KV Cache 先数元素，再乘 batch、层数与 dtype

MHA = B × T × L × 2H D × bytes
GQA = B × T × L × 2G D × bytes
ToyMLA = B × T × L × latent × bytes
MLA(core) = B × T × L × (d_c + d_h^R) × bytes

CACHE LAB

训练 / Prefill

整段 token 可以并行，注意力分数含 [B,H,T,T]。GQA 减少 K/V 投影，但不会把每个 Q 头对应的注意力矩阵删掉。

逐 token Decode

每步只有一个新 Query，却要读取长历史的 K/V。此时 cache 体积与内存带宽更容易成为瓶颈，MQA/GQA/MLA 的价值更直接。

PDF 第 7 页算术纠正4096 × 8 / 32 = 1024，不是 102。若同时统计 K 和 V，GQA 每 token、每层应是 2×1024=2048 个元素；MHA 是 2×4096=8192。

四组最容易混淆的写法

通常调用前者。nn.Module.__call__ 会处理 hooks、自动混合精度相关包装等，再进入 forward。

永远表示最后一个轴，但最后轴的“业务含义”会变：scores 中是 Key 位置；router 概率中是专家。

第 10 课 · 相邻扩展：Mixture of Experts

注意力让 token 互相读；MoE 决定 token 去哪间 FFN

MHA / GQA / MLA

发生在注意力子层。输入一个 token 的 Query，读取序列中可见 token 的 K/V；KV Cache 属于这条路线。

Top-K MoE

通常替换 FFN 子层。router 对每个 token 选 K 个专家；专家本身不负责在 token 之间传递信息。

p = softmax(router(x), dim=-1)
weights, ids = p.topk(K, dim=-1) # PyTorch 返回 (values, indices)
gate = weights / weights.sum(dim=-1, keepdim=True)
y = Σ gateᵢ × Expert[idsᵢ](x)

两份代码的审计结论

attention_variants_demo.py
明确缺失

没有输出投影 WO

因此三个类都是核心数据流演示，不是完整注意力层。

形状检查

C % H 未验证

实现边界

没有真实 cache / decode

性能边界

GQA 物理复制 K/V

repeat_interleave 便于教学，不代表高效 kernel。

模型边界

ToyMLA 省略 RoPE 与矩阵吸收

不能复现真实 MLA 缓存、速度或效果。

moe_router_demo.py
训练缺陷

均衡指标不可微

硬 top_ids + bincount 无法给 router 梯度。

参数边界

没有校验 1≤K≤E

K=0 会除零，K>E 会使 topk 报错。

系统边界

无容量、丢弃和通信

生产 MoE 还需 expert capacity、分布式派发与 all-to-all。

性能边界

Python if 导致 GPU 同步

if selected.any() 适合小例子，不适合高吞吐。

解释边界

随机路由没有语义

固定种子只保证可复现；专家尚未训练，不能称为“数学专家”等。

深入题：先自己说 30 秒，再展开

题 1：为什么 C=30、H=4 会在 MHA 的 view 处失败？

用整数除法和元素总数解释。

D=30//4=7，四个头只能容纳 4×7=28 个通道；但 q 实际仍有 30 个通道，元素总数对不上。构造时应先检查 C % H == 0。

题 2：为什么 transpose 后常用 reshape，而不是直接 view？

区分逻辑轴顺序与物理内存 stride。

transpose 通常只改变 stride，不重排底层数据，张量可能非连续。view 需要兼容 stride；reshape 必要时会生成连续副本，因此在合并头时更稳。

题 3：H=8、G=2 时，GQA 为什么仍有 8 张注意力权重图？

共享 K 与 Query 是否相同是两回事。

八个 Query 头都有不同 Q，因此即使四个 Q 头共享同一个 K/V 组，各自的 QKᵀ 分数和 softmax 权重仍不同。共享减少的是 K/V 的独立表示与缓存。

题 4：为什么 ToyMLA 的两层线性映射构成低秩约束？

中间 latent 维度是 r。

没有激活时复合矩阵为 W_restore @ W_compress，其秩不超过中间维 r。r<C 时，它不能表示任意 C→2C 线性映射，这正是压缩与表达约束的交换。

题 5：为什么脚本的 causal_attention 不能直接用于增量 KV Cache？

比较 Query 长度和 Key 历史长度。

函数从 q 取一个 time，并创建 time×time 方阵，假设 q/k/v 等长。增量解码常为 Tq=1、Tk=历史长度+1；还需接收旧 cache、拼接新状态并返回更新后的 cache。

题 6：Top-2 概率 [0.50,0.25] 为何要再归一化？

先算和，再解释加权输出尺度。

原和为 0.75；除以 0.75 后得到 2/3 与 1/3，入选专家贡献和为 1。若不重归一，丢弃专家的概率质量会让输出整体缩小，改变层的尺度。

题 7：如何构造一个最小的可微教学版负载损失？

不要从整数 top_ids 开始。

可先用 mean_probability = probabilities.mean(dim=0)，再与均匀目标 1/E 做 MSE。它仍不是完整生产方案，但保留了从 loss 到 router 概率的梯度。

题 8：为什么“MQA 最快、MHA 最强”不能当成无条件排名？

至少列出四个控制变量。

速度受 batch、上下文、prefill/decode 比例、硬件带宽、并行策略与 kernel 影响；质量受参数规模、数据、训练预算、权重转换与评测任务影响。结构给出倾向，不给出跨场景的绝对名次。
