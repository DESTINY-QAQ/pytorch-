关卡 0 · 建立正确地图

先修正一个会影响整篇理解的词义混淆

课件的主题是“词嵌入”，但它在部分段落里把三种不同对象都叫 embedding。新手如果不先分开，后面很容易以为 Transformer 每次都在修改查表结果。

① Token ID

只是词表索引，例如“猫”是 0。“0 比 4 小”没有语义意义。

dtype=torch.long

② 输入 token embedding

参数矩阵 E[V,C] 的某一行。同一 token ID 在同一模型中先查到同一行。

x = E[token_id]

③ 上下文 hidden state

输入向量经过注意力、FFN 和多层堆叠后的结果；同一 token 会随句子改变。

h = Transformer(x, context)

④ 输出 embedding / 输出权重

Word2Vec 常有输入表和输出表；语言模型的词表输出层也可能与输入表共享权重。不要默认只有一张表。

本课的总心智模型Embedding 层本身是一张可训练查找表；“动态上下文表示”不是查表结果自动变化，而是后续网络读取上下文后计算出来的新向量。

关卡 1 · Python / PyTorch 预备

nn.Embedding 到底做了什么？

它最像“按 ID 取数据库的一行”，不是把整数做普通数学运算。词表大小为 V，向量维度为 C，参数矩阵形状就是 [V,C]。

token IDs [B,T]→按 ID 查 E 的行→vectors [B,T,C]

Python 层面

ids 是整数张量；emb(ids) 像函数调用，PyTorch 实际执行模块的 forward。

训练层面

emb.weight 是 nn.Parameter。反向传播为参与本批次的行计算梯度，优化器再更新它们。

关卡 2 · PDF p.2-3

Word2Vec：让“常在相似环境出现”的词靠近

Word2Vec 不是一份固定词典，而是两个训练架构的统称。数据没有人工语义标签；监督信号来自文本自己，所以今天更精确地说，它是自监督表示学习。

Skip-gram

输入：中心词

预测：窗口内每个上下文词

直觉：一个中心词产生多条训练对。

CBOW

输入：窗口内上下文集合

预测：中间中心词

直觉：先把上下文向量求和或平均。

互动实验 2：滑动窗口怎样制造训练样本？

点任意 token 设为中心词，再改变窗口大小。

WINDOW LAB

绿色是上下文，蓝色是中心词。语料边缘的 token 上下文更少；真实训练还常对高频词做下采样。

为什么需要负采样？

如果词表有 50,000 个 token，每条样本都做一次 50,000 类 softmax 很贵。负采样改成：看一个真实中心-上下文对，再抽少量噪声词，做若干 sigmoid 二分类。

maximize log σ(ucontext · vcenter) + Σ log σ(−unegative · vcenter)正对的点积要大，负对的点积要小。v 来自输入表 W_in；u 来自输出表 W_out。

互动实验 3：负采样损失计算器

拖动点积。观察“正例很像、负例不像”时损失怎样下降。

LOSS LAB
为什么相似词会靠近？这是合理推测，不是逐条硬规则如果“猫”和“狗”经常面对相似上下文词，它们必须产生相似的预测分布；共享低维参数会促使向量呈现相似几何结构。但语料偏差、频率、采样策略和维度都会影响结果，不能把单个余弦值当“语义真相”。

关卡 3 · PDF p.3-4

GloVe：先数全局共现，再拟合对数统计

Word2Vec 在局部窗口上逐样本预测；GloVe 先把整个语料的窗口共现聚合成 Xᵢⱼ。它们使用的信息都来自共现，但优化接口不同。

J = Σi,j f(Xij) · (wi·w̃j + bi + b̃j − log Xij)²只有 Xᵢⱼ > 0 的项进入标准目标；f(X) 限制超高频项的支配作用，并降低稀有共现的影响。

关卡 4 · PDF p.5-8

Transformer：Embedding 是入口，hidden state 才是上下文表示

BERT/GPT 不再用 Word2Vec 的独立目标预训练输入表，而是把 embedding 放进整台模型，让语言建模 loss 沿整条计算图反向传播。

Token/Position静态查表
Layer 1读取邻近线索
Layer 2…N融合更多上下文
LM Head输出词表 logits

互动实验 5：同一个“苹果”在哪里开始不同？

切换句子：token embedding 分量保持相同；合成输入还可能因位置/句段而不同，层后 hidden state 则会读取上下文。

CONTEXT LAB

BERT 与 GPT：预测任务不同，梯度来源相同

BERT 的一个关键梯度细节当输入位置被替换成 [MASK] 时，该位置前向输入的是 [MASK] 的向量，不是答案词向量。答案词的输入 embedding 仍可能通过它在其他未遮盖位置出现、以及输入/输出权重共享等路径得到更新；不能简单说“这个遮住词的 embedding 在该位置直接被修正”。

子词 embedding：解决的不是“语义自动拼接”

子词 tokenizer 在词表大小与序列长度之间折中。例如 playing → play + ##ing，两个子词各自查表，再由 Transformer 组合上下文。它提高新词和词形变化的覆盖，但不保证任意切分都自然，也不自动给出一个唯一“整词向量”。

保证可表示

字节级 BPE 或明确的字符/字节回退可以把任意输入拆到底层单元。

仍可能未知

没有完整基础字母表或回退机制的 WordPiece/BPE，仍可能输出 [UNK]。

关卡 5 · PyTorch 训练循环

一个 embedding 行究竟怎样被改动？

训练不是“把词义写进向量”的神秘过程，而是反复执行：查表 → 算 logits → 算 loss → 求梯度 → 更新参数。

zero_grad()→forward()→loss→backward()→step()

互动实验 6：浏览器里真的做一次梯度更新

这是一个 2 维 embedding + 2 类输出层。点“训练一步”，数字会按交叉熵梯度更新。

TRAINING LAB

为了看清更新，演示不使用 AdamW，只做最基础的梯度下降。PyTorch 自动微分会得到同类梯度；优化器规则决定如何把梯度转成更新。

loss.backward()

只计算并累积 .grad；参数数值还没变。

optimizer.step()

读取梯度并真正修改参数，包括 embedding 与输出层。

只更新被查到的行，不等于只有这些参数变化当前 batch 没出现的 embedding 行通常没有输入侧任务梯度；但输出层可能为许多或全部词产生梯度，输入/输出权重共享也会改变更新路径。若优化器使用解耦权重衰减（如 AdamW），即使任务梯度为 0，未命中行也可能因权重衰减而发生微小变化。

关卡 6 · 易错点

六个新手最容易带走的错误结论

错误想法为什么错正确检查方式
“ID 之间有远近”ID 只是行号；更换词表顺序不会改变语义。比较向量前先确认同一模型、同一层和同一归一化方法。
“Embedding 自己理解上下文”输入查表没有读取别的 token。问清对象是 embedding.weight 还是层后 hidden_states。
“余弦相似就是词义真值”结果受语料、频率、偏差和层选择影响。把它当模型行为测量，并在任务数据上验证。
“负采样只是少算几个类别”它改变了训练目标，并引入噪声分布与输入/输出双表。明确写出正负 sigmoid 目标与采样分布。
“BERT 的 [MASK] 词向量被直接修正”该输入位置看到的是 [MASK] 向量；答案用于 loss。沿计算图追踪输入、输出层和权重共享。
“子词永远没有 OOV”是否保证覆盖取决于基础字母表和回退机制。用罕见字符、emoji、混合脚本做 tokenizer 测试。

关卡 7 · 深入理解与长期记忆

先尝试回答，再展开思路

这些题没有单一关键词答案，目标是检查你能否沿数据流解释。建议先用自己的话说 30 秒，再点“显示思路”。

题 1：为什么两个从未同时出现的词，最后仍可能向量相近？

请从“共享上下文”和“共享参数”解释，不要只回答“因为语义相近”。

它们不必直接共现。如果 A 和 B 都经常与一组相似上下文 C、D、E 共现，那么为了产生相似预测分布，优化器可能把 A、B 的输入向量推到相近区域。这是分布假设的体现，但不是数学保证。

题 2：BERT 句子中的“苹果”为什么能变化，而 embedding 表的“苹果”又不变化？

至少说出两个不同时间尺度：一次 forward 内、很多训练 step 之间。

一次 forward 内，同一参数表在两个位置查出的输入行相同，但两条上下文经过注意力后得到不同 hidden state。跨训练 step 看，优化器会缓慢修改参数表本身；下一次 forward 再查表时，所有语境共享这个更新后的起点。

题 3：如果把 embedding 维度从 128 增到 4096，会必然更好吗？

请给出至少三个可能的代价或反例。

不必然。参数量和显存近似随 V×C 增长；计算成本也上升；小语料更易过拟合；优化更难；下游模型的维度必须匹配；若任务信号不足，多出的维度不一定学到稳定结构。要在验证集与资源预算下比较。

题 4：怎样证明“loss 下降”不是模型只在背训练语料？

设计一个最小实验，说明数据划分、指标和预期现象。

保留未参与训练的验证句子，固定 tokenizer 与词表，同时记录 train/validation loss，并用新上下文做最近邻或预测测试。训练 loss 降而验证 loss 升通常提示过拟合；两者都下降才更支持泛化，但仍要看任务指标和误差案例。
