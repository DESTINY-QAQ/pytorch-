符号不是装饰：它们决定代码的结构

点一个符号，看它在本文件中的角色

四种“定义”和“执行”不要混

源码写法看到这行时什么时候真正执行内部逻辑

class CBOW(...):创建类对象CBOW(len(vocab)) 创建实例时运行 __init__

= 与 ==

= 把右边对象绑定给左边名字；== 比较两个值是否相等。step == 1 绝不是赋值。

可变列表与不可变整数

append 会原地修改列表；i + 1 创建新整数值。理解“是否原地修改”对读训练代码很重要。

类型提示不是运行检查

steps: int 能帮助 IDE 与人阅读；如果直接调用 main("400")，Python 不会仅凭注解自动拒绝。

点号后的名字来自对象

torch.optim.AdamW 是模块层层访问；loss.item() 是 Tensor 的方法；parsed.steps 是命令行结果的属性。

Python 对 class、实例方法与 self 的正式说明见 Python Classes 教程；命令行解析见 argparse 文档。

关卡 3 · 从字符串到监督学习样本

最密集的 Python 语法，集中在 5 行预处理里

点击左侧表达式，把“聪明的一行”展开为普通循环。推导式不是新算法，只是更紧凑的写法。

用一条句子手工走完 build_examples

句子 tokens： [猫, 喜欢, 吃, 鱼]
对应 IDs：    [8,   3,   1, 11]

i = 1：context = [8, 1]  → target = 3     # [猫, 吃] → 喜欢
i = 2：context = [3, 11] → target = 1     # [喜欢, 鱼] → 吃

contexts = [[8, 1], [3, 11]]   # shape [2,2]
targets  = [3, 1]               # shape [2]
为什么不让 i 从 0 开始？i=0 没有左邻居；i=n−1 没有右邻居。range(1, len(token_ids)-1) 正好只访问有完整两侧上下文的位置。

关键审计：句子边界被删除了

这里要直接纠正一个容易忽略的前提“这是教学玩具”可以解释语料小，却不能自动让跨句伪样本变正确。它们会教模型虚构的相邻关系，且比例高达 45.4%。因此最近邻输出不仅不代表真实词义，也混入了错误的数据信号。

如果修复，数据构造应保留句界

context_parts, target_parts = [], []
for sentence in SENTENCES:
    sentence_ids = [stoi[word] for word in sentence.split()]
    c, t = build_examples(sentence_ids)
    context_parts.append(c)
    target_parts.append(t)

contexts = torch.cat(context_parts, dim=0)  # [960, 2]
targets = torch.cat(target_parts, dim=0)    # [960]

这段是讲解中的修正方案，原始 embedding_training_demo.py 未被改动。另一个边界情况：若传入少于 3 个 ID，原函数会得到形状 [0] 的空 context Tensor，而不是预期的 [0,2]；Embedding 随后给出 [0,D]，mean 又变为 [0]，最终 Linear 因最后一维不是 D 而失败。

关卡 4 · nn.Module 与张量形状

模型不是“一个公式”，而是两张参数表加一条数据路线

IDs [B,2]→查表 [B,2,D]→平均 [B,D]→Linear [B,V]

互动：逐步追踪本文件的真实形状

字母本例实际值含义在哪一行消失/出现
B / N1758训练样本数；这里全量一次送入，不是常见小批次交叉熵默认 mean 后消失
22左右两个 context 位置mean(dim=1) 后消失
D16每个词向量的维度Embedding 添加，Linear 消耗
V12词表大小，也是分类类别数Linear 输出端出现

互动：V 和 D 改变时，参数量如何变？

拖动词表大小和向量维度。该模型有两张 [V,D] 权重，Linear 另有 V 个偏置。

PARAMETER LAB

源码默认 V=12、D=16，所以总参数为 12×16 + 12×16 + 12 = 396。

nn.Embedding(V,D)

把整数 ID 当行号查参数矩阵。输入任意形状 *，输出在末尾追加 D：* → *,D。

nn.Linear(D,V)

对最后一维做 y=xAᵀ+b，保留前面的 batch 维。其权重布局是 [out,in]=[V,D]。

mean(dim=1)

dim 从 0 数起：0 是样本轴，1 是两个 context，2 是向量分量。沿 dim=1 平均后它消失。

model(contexts)

不要习惯直接调用 model.forward(...)。Module 的调用包装负责钩子等机制，然后才进入 forward。

以上行为可在 nn.Module、nn.Embedding 与 nn.Linear 官方文档核对。

关卡 5 · 训练循环与自动微分

预测、评分、归因、更新：四件事不要揉成一件

一条样本的交叉熵，手算到数字

假设三个类别的 logits = [2.0, 1.0, 0.0]，正确类别是 0
softmax 后概率       ≈ [0.665, 0.245, 0.090]
loss = -log(0.665)   ≈ 0.408

若把正确类别 logit 从 2.0 提高到 3.0：
正确概率变大 → loss 变小 → 这是梯度希望推动的方向
高频错误：先 softmax 再交叉熵。F.cross_entropy 需要原始、未归一化 logits，并内部进行数值稳定的 log-softmax 组合。把概率再传进去会改变目标并降低数值稳定性。

为什么先重置梯度？

PyTorch 默认把新梯度累加到已有 .grad。普通训练每轮要先重置；当前 zero_grad() 默认将它设为 None，只有 set_to_none=False 才填零。

为什么 loss 是标量？

源码的交叉熵默认对 1758 个样本求平均。标量方便从一个总目标反向传播。

为什么 item()？

它从单元素 Tensor 取出普通 Python 数字，便于格式化打印；它不参与后面的梯度计算。

AdamW 还做了什么？

除自适应更新外，源码省略的 weight_decay 使用默认值 0.01。想明确教学行为，最好显式写出。

打印条件也值得逐符号读

if step == 1 or step % max(1, steps // 5) == 0:
    print(f"step {step:>4}/{steps}: loss={loss.item():.4f}")

steps = 400 时：steps // 5 = 80
因此在 step 1、80、160、240、320、400 打印
:>4  → 宽度 4、右对齐          :.4f → 小数点后 4 位
时间点细节：这里打印的 loss 来自本轮 optimizer.step() 之前那次 forward。step() 已更新参数，但 loss.item() 只是读取旧 loss Tensor 的数值，不会用新参数自动重算。

交叉熵输入/目标形状见 F.cross_entropy 官方文档；梯度重置的默认行为见 Optimizer.zero_grad 官方文档；AdamW 默认项见 AdamW 官方文档。

关卡 6 · 从向量到最近邻

normalize + @ + topk 在做什么？

余弦相似度(a,b) = (a·b) / (‖a‖₂‖b‖₂)；若两者先单位化，就只剩 a·b

互动：观察“自身”为什么总排第一

下面使用明确标注的人工向量，只演示运算，不冒充脚本训练结果。

COSINE LAB

Top-4

with torch.no_grad()

临时不记录梯度，适合检查/推理。它不冻结参数、不会清空旧梯度，也不等同于 model.eval()。

dim=-1

-1 表示最后一个轴。对 [V,D] 的最后轴归一化，就是让每个词向量各自长度为 1。

vectors @ vectors[id]

[V,D] @ [D] → [V]，一次得到查询词与词表全部行的相似度。

topk(...).indices.tolist()

先取 Top-K 结果对象的索引 Tensor，再转成 Python 列表，随后用 itos[i] 还原词。

三个不同开关no_grad() 控制是否建求导图；zero_grad() 清参数已有梯度；model.eval() 切换 Dropout/BatchNorm 等层的训练行为。本模型只有 Embedding 和 Linear，因此 eval 不会改变输出，但概念仍不能混。

no_grad、normalize 与 topk 的官方说明。

关卡 7 · 像工程师一样审计代码

区分“明确缺陷”“教学简化”和“不能从结果推出的结论”

明确缺陷 · 高影响

句子边界丢失

798 条伪样本，占 45.4%。这会改变训练分布，应该按句分别构造窗口后再拼 Tensor。

明确缺陷 · 边界输入

steps≤0 与短 token 列表没有校验

--steps 0 会输出未训练向量；少于 3 个 ID 会生成错误形状的空 context。更稳的代码应提前 raise ValueError。

展示偏差

Top-K 默认包含查询词

自身相似度约为 1。若目标是找“其他近邻”，应先把查询位置分数设为 -inf 或多取一个后过滤。

未显式参数

AdamW 默认权重衰减 0.01

源码只写了学习率，不代表没有权重衰减。教学代码显式写 weight_decay=0.01 或 0 更清楚。

合理简化

全量 batch、无验证集、无 DataLoader

用于看懂 API 可以接受；若目标变成可靠训练，就需要 mini-batch、shuffle、验证集、设备管理、checkpoint 与更大语料。

模型边界

没有词序、未知词和上下文表示

mean 让左右顺序不可辨；词表外输入会 KeyError；一个词只有一行静态输入向量。这些都是 CBOW 与 Transformer 的结构差异。

进阶 API 陷阱

不要只把 Embedding 改成 sparse=True

这会让其权重得到稀疏梯度，而 AdamW 不在官方列出的稀疏梯度优化器中；需要同时选择受支持的优化器并重新确认其余参数的优化方式。

可复现性边界

manual_seed 不是跨平台位级保证

固定随机种子能让同环境中的初始化更可重复，但不同 PyTorch 版本、设备或非确定性算法仍可能产生差异。

参数语义

输入表与输出层是两张权重

model.embedding.weight 是输入词向量；model.output.weight 是分类权重。两者形状都为 [V,D]，但参数独立，源码最终只检查前者。

深入题：先用自己的话说 30 秒

题 1：为什么把 5 个句子重复 80 次，不等于模型看到了更多语言规律？

请同时考虑“独特样本数”和默认 mean loss。

重复不会创造新的词或上下文。若按句正确构造、全量计算并对所有样本取平均，每条样本重复相同次数时，平均梯度与只用一份几乎相同；主要增加计算量。当前源码因跨句拼接，还额外重复了错误边界模式。

题 2：为什么 mean(dim=1) 让 [猫, 吃] 与 [吃, 猫] 完全无法区分？

请用加法交换律解释。

两者分别得到 (E猫+E吃)/2 与 (E吃+E猫)/2；加法满足交换律，所以结果完全相同。若需要区分左右，可分别投影、拼接，或加入位置表示/注意力机制。

题 3：为什么 Linear 权重会为许多词得到梯度，而输入 Embedding 通常只更新被查到的行？

沿前向图比较“查表”和“全词表分类”。

Embedding 前向只读取 context IDs 对应的行，任务梯度沿这些查表路径返回。Linear 为每个样本输出全部 V 个 logits，交叉熵对多个类别的 logit 都有梯度，所以输出权重的许多行会参与更新。默认 dense Embedding 中，整张 Parameter 的 .grad 存在而未命中行可为零；AdamW 仍可对这些行施加权重衰减。若某个完整 Parameter 的 .grad is None，优化器通常跳过它。

题 4：若想把 context 从左右各 1 个词改为左右各 2 个词，哪些地方必须同步变化？

至少回答样本构造、输入形状、mean 和边界。

循环应写成 range(2, len(token_ids) - 2)，实际产生索引 2…n−3；每条 context 收集 i−2、i−1、i+1、i+2，形状变成 [B,4]；Embedding 输出 [B,4,D]；仍可对 dim=1 求平均；每句少于 5 个词时没有样本，且仍必须逐句处理边界。

题 5：如何证明 loss 下降不是“学会真实词义”？

设计一个最小验证，而不是只看训练打印。

保留未参与训练的新句子或新上下文，分别记录 train/validation loss；再设计不依赖训练句复述的类比、最近邻或预测任务，并与随机/频率基线比较。训练 loss 下降只确认模型更会拟合训练目标，不足以证明泛化或语义有效。
